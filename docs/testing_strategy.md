# 测试策略：覆盖可用性

## 核心原则

**不能等遇到 bug 才加检查。必须在写代码时就系统性覆盖所有用户路径。**

## 方法：用户操作矩阵测试

每个功能上线前，列出所有用户能做的操作组合，逐一自动化验证。

### 操作矩阵模板

| 点击按钮 X | 状态 A | 变为状态 B | 连续快速点击？网络断开？数据为空？ |

## 未知 bug 防御策略

### 防御性编码

1. **所有异步操作加版本号** — 丢弃过期响应
2. **所有列表加空状态** — 永远不出现无解释的空白
3. **所有按钮加 loading 状态** — 防止重复点击
4. **所有网络请求加 timeout + 错误处理** — 不静默失败
5. **所有状态转换加日志** — 出问题能追溯

### 猴子测试思维

写完功能后问自己：
- 如果用户疯狂点击会怎样？
- 如果网络延迟 5 秒会怎样？
- 如果数据为空/超大会怎样？
- 如果在操作中途切换页面会怎样？
- 如果两个操作几乎同时触发会怎样？

### 测试覆盖度量

| 层级 | 当前 | 目标 |
|------|------|------|
| 后端单元测试 | 200 | 覆盖所有解码器 + 过滤器 |
| 后端 E2E (WebSocket) | 13 | 覆盖所有用户路径 |
| 前端组件测试 | 29 | 覆盖所有交互状态 |
| 浏览器 E2E | 0 | **必须加** |
