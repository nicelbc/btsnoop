# 代码 Review 检查清单

每次提交前必须逐项检查，不通过不许提交。

## 1. 异步/WebSocket 竞态检查

- [ ] 用户能否快速连续触发同一操作？（快速点击按钮、切换 tab）
- [ ] 如果能，前一个请求的响应会不会覆盖后一个请求的结果？
- [ ] 是否有版本号/请求 ID 机制丢弃过期响应？
- [ ] WebSocket 消息顺序是否可能乱序？处理了吗？

## 2. 状态同步检查

- [ ] 同一个数据在前端有几处来源？（props、store、local state、WebSocket）
- [ ] 多个组件操作同一个状态时，是否存在不同步？
- [ ] 过滤/搜索逻辑是前端做还是后端做？是否有重复/冲突的两层过滤？
- [ ] UI 组件高亮状态是否与实际数据状态一致？

## 3. 按钮/交互可用性检查

- [ ] 按钮 disabled 条件是否合理？初始状态能不能点？
- [ ] 发起连接的按钮不应该依赖"已连接"状态
- [ ] 空列表/无数据/加载中是否有提示？不能是空白
- [ ] 错误状态是否有明确的用户提示？

## 4. 路由/中间件冲突检查

- [ ] 新加的路由是否被 catch-all 拦截？（特别是 WebSocket 路径）
- [ ] 中间件（CORS、静态文件）是否影响 API/WS 端点？
- [ ] 代理配置（vite proxy）是否覆盖了所有需要转发的路径？

## 5. 数据流端到端检查

- [ ] 从用户操作 → 前端请求 → 后端处理 → 响应 → 前端渲染，完整跑通了吗？
- [ ] 不是"后端 API 能返回正确数据"就够，必须验证前端拿到后能正确渲染
- [ ] 大数据量场景（1000+ 包）和小数据量场景（0 包）都测了吗？

## 6. 前后端接口对齐检查

- [ ] 前端发送的字段名与后端期望的一致吗？（如 `cmd` vs `action`）
- [ ] 后端返回的 JSON 结构与前端 TypeScript 类型定义匹配吗？
- [ ] 枚举值大小写一致吗？（`AVDTP` vs `avdtp`）

## 7. 模式区分检查

- [ ] Demo/测试数据与真实数据是否有明确的视觉区分？
- [ ] 用户能否分辨当前是模拟还是真实？
- [ ] 不同模式（上传/实时/Demo）的代码路径是否都测试过？

## 8. 性能/体验检查

- [ ] 实时流场景下，数据延迟是否可接受？
- [ ] 大文件上传/解析是否有进度提示？
- [ ] 列表过滤后是否即时响应？切换是否有闪烁？

---

## 提交前必做动作

```
1. TypeScript 编译通过 (npx tsc --noEmit)
2. 后端全量测试通过 (pytest tests/ -q)
3. 前端测试通过 (npx vitest run)
4. 启动前后端，在浏览器中实际操作验证功能
5. 快速切换/连续点击测试竞态
6. 空数据/无设备/网络断开等边界场景
```
